## 📸 Features

- 🎙️ **Audio Transcription** — Upload MP3, WAV, MP4, M4A files and get accurate transcripts
- 👥 **Speaker Diarization** — Automatically identifies and labels multiple speakers (Speaker A, B, C...)
- 🏷️ **Speaker Naming** — Optionally assign real names to each speaker before processing
- 📝 **AI Summarization** — Concise 2-3 sentence meeting summary generated by LLM
- ✅ **Action Items Extraction** — All tasks and assignments automatically pulled out
- 🔑 **Key Decisions** — Important decisions made during the meeting highlighted
- 💬 **RAG Chatbot** — Ask questions about any meeting using semantic search over the transcript
- 🗄️ **Meeting History** — All meetings stored and accessible anytime

## 🔧 Tech Stack

| Layer | Technology | Purpose |
|---|---|---|
| Frontend | Vanilla HTML/CSS/JS | Upload UI, meeting dashboard, chat interface |
| Backend | Flask + SQLAlchemy | REST API, routing, database ORM |
| Database | SQLite | Meeting storage (transcripts, summaries, status) |
| Transcription | AssemblyAI (`universal-2`) | Speech-to-text + speaker diarization |
| LLM | Groq (`llama-3.3-70b-versatile`) | Summarization, action items, decisions |
| Embeddings | HuggingFace (`all-MiniLM-L6-v2`) | Local CPU embeddings for RAG |
| Vector Store | FAISS | Semantic search over transcript chunks |
| RAG | LangChain | Retrieval-augmented chatbot pipeline |
| Deployment | Render (free tier) | Cloud hosting |

## 🔄 How It Works

### Upload & Transcription Flow
```
User uploads MP3/WAV
      ↓
Flask saves to /uploads
      ↓
AssemblyAI transcribes + diarizes
      ↓
Speaker labels assigned (A, B, C... or custom names)
      ↓
Transcript stored in SQLite
```

### Summarization Flow
```
Transcript fetched from DB
      ↓
Truncated to 8000 chars (if needed)
      ↓
Groq LLM (llama-3.3-70b) called with structured prompt
      ↓
JSON parsed → summary, action_items, decisions extracted
      ↓
Results saved to DB
```

### RAG Chatbot Flow
```
User asks a question
      ↓
Transcript split into 400-char chunks (40-char overlap)
      ↓
Chunks embedded with all-MiniLM-L6-v2 (local, free)
      ↓
FAISS retrieves top-3 relevant chunks
      ↓
Groq LLM answers using retrieved context only
      ↓
Answer returned to user
```

## 🚀 Local Setup

### Prerequisites
- Python 3.11+
- Node.js (for localtunnel, optional)
- API keys: AssemblyAI, Groq

### 1. Clone the repository
```bash
git clone https://github.com/Masterjai05/MeetMind.git
cd MeetMind
```

### 2. Create and activate virtual environment
```bash
python -m venv venv

# Windows
venv\Scripts\activate

# Mac/Linux
source venv/bin/activate
```

### 3. Install dependencies
```bash
pip install -r requirements.txt
```

### 4. Set up environment variables
Create `backend/.env`:
```env
GROQ_API_KEY=your_groq_api_key_here
ASSEMBLYAI_API_KEY=your_assemblyai_api_key_here
HF_TOKEN=your_huggingface_token_here
```

Get your free API keys:
- **Groq**: [console.groq.com](https://console.groq.com)
- **AssemblyAI**: [assemblyai.com](https://www.assemblyai.com)
- **HuggingFace**: [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)

### 5. Run the Flask backend
```bash
cd backend
python app.py
```

### 6. Open the frontend
Open `frontend/index.html` in your browser or serve it with Live Server in VS Code.

## ☁️ Deployment (Render)

### 1. Push to GitHub
```bash
git add .
git commit -m "initial commit"
git push origin main
```

### 2. Deploy on Render
1. Go to [render.com](https://render.com) → New → Web Service
2. Connect your GitHub repository
3. Configure:
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `gunicorn --chdir backend app:app --bind 0.0.0.0:$PORT --timeout 120`
4. Add environment variables:
   - `GROQ_API_KEY`
   - `ASSEMBLYAI_API_KEY`
   - `HF_TOKEN`
   - `PYTHON_VERSION` = `3.11.0`
5. Click **Deploy**

## 📊 Accuracy & Performance

| Feature | Accuracy |
|---|---|
| Transcription (clean audio) | 90–95% |
| Speaker diarization (2–4 speakers) | 85–92% |

### Recommended Audio Specs
- **Format**: MP3 or WAV
- **Duration**: 5–15 minutes (sweet spot)
- **Speakers**: 1–6 (up to 10 supported)
- **Sample rate**: 16kHz or higher
- **Background noise**: Minimal for best results

## 💡 Key Design Decisions

**Why AssemblyAI over Whisper?**
AssemblyAI is a cloud API — no heavy ML packages needed on the server. Whisper requires PyTorch (2–4GB) which crashes Render's free tier (512MB RAM). AssemblyAI handles transcription + diarization in one API call with 90–95% accuracy.

**Why Groq over OpenAI/Gemini?**
Groq offers 30 RPM and 14,400 requests/day on the free tier with extremely fast inference on custom LPU hardware. The llama-3.3-70b model performs comparably to GPT-3.5 for structured extraction tasks.

**Why FAISS over Pinecone?**
FAISS is in-memory — no external service, no API cost, zero latency for small datasets. For single-meeting Q&A with a few hundred chunks, FAISS is faster and simpler. Pinecone adds value at scale but is overkill here.

**Why 400-char chunk size for RAG?**
400 chars (~60–80 words) captures roughly one speaking turn. Too small loses context; too large makes retrieval imprecise. 40-char overlap ensures sentences split across chunks are retrievable from either side.
